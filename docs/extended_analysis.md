# Frozen secondary multi-axis analysis

**Definitions fixed 2026-10-25 16:29 UTC, before this analyst inspected real software or QA correctness outputs.** These are supplemental, descriptive analyses of the prospectively configured studies, not new primary endpoints or a way to replace an unfavorable result. No new model call, prompt change, training, or candidate selection is performed. Run only on a completed study directory; a recorded `summary.json` completion marker and the declared number of trials/items are required. The separately preserved interrupted QA runtime run is operational evidence and is not pooled with the clean complete run.

## Software definitions

1. **Treatment strength:** pair traces by task, generation seed and attempt; count action disagreements and complete-pair coverage, separately by attempt. An identical action is not a successful additional treatment. Different realized feedback legitimately changes later context; this is not a randomized mediation estimate.
2. **Same-suite revision:** final minus retrospectively adjudicated initial hidden pass fraction. Report mean, improved/tied/worsened fractions, complete repairs (initial failed suite → final passed suite), regressions (initial passed suite → final failed suite), and same-case repair/regression counts. Both hidden evaluations occur only after generation and never choose a candidate. Public-diagnostic versus hidden differences remain explicitly confounded and are not used as revision evidence.
3. **Efficiency conditional on correctness:** among final candidates passing every hidden test, report line events, traced peak bytes, candidate execution time and fourfold-input line-event ratio. Also report the eligible fraction. These quantities include harness/output effects, do not prove asymptotic bounds, and different sets of correct tasks can confound condition means.
4. **Realized cost and token-normalized quality:** report all model/feedback/evaluator calls, prompt and completion token coverage, total reported tokens and mean per trial. Descriptive quality per 1,000 reported tokens is `1000 * sum(final hidden pass fraction) / sum(reported tokens)` on the identical subset with reported usage. Also report completion-only normalization. This is a cost-efficiency ratio, not a second correctness score or an assertion of equal consumed tokens. Inputs and outputs are both counted in the principal denominator; inference latency is descriptive and hardware/scheduling-dependent.
5. **Failure and uncertainty profiles:** separately count source/schema/provider errors, setup/runtime failures, functional wrong cases without a runtime error, and resource compliance. Scores may overlap and are not summed into one quality index. Full-suite confidence is self-reported; report coverage, Brier score and ten-bin chosen-confidence calibration against all-tests success, with bin counts. No confidence is invented when absent.
6. **Diversity and complexity:** report valid-source AST hash diversity, declared operation-signature diversity, source length, AST nodes and cyclomatic proxy. These are implementation/surface proxies; neither new variable names nor new ASTs establish useful or published novelty.
7. **Descriptive Pareto comparison:** a condition dominates another only if it has at least as high mean hidden pass fraction and full-suite success, and at most as many mean total reported tokens, with at least one strict inequality. Require identical task/seed coverage and complete token reports. No latency or correct-only memory is mixed into that frontier because their conditional/noisy comparisons can be misleading. The frontier has no uncertainty-based superiority interpretation and no scalar aggregate is produced.

Trial records remain paired by task and seed. Software uncertainty remains the primary runner's task-cluster interval; secondary metrics are descriptive and not multiplicity-corrected. Six tasks and two generation seeds provide only six task clusters. The fixed transferred controllers were trained on a different procedural grammar, and pretrained-model contamination remains unknown.

## QA definitions

The strict existing `evaluate_answers` result remains **primary**. It requires the exact answer/probability schema and retains every malformed, failed or abstained attempt. Brier/log score and decision calibration apply only where distributions are valid; their coverage stays visible.

Two explicitly secondary diagnostics separate extractable choices from probability/schema compliance:

- **Direct JSON choice:** parse the entire response as one completed JSON object and accept only a string `answer` exactly equal to one offered label. Other fields, probability normalization and probability completeness do not determine this choice-only result. Null is an abstention, not an answered choice. JSON syntax must be valid; a duplicated top-level `answer` is rejected as ambiguous. The parser never reads gold during extraction.
- **Exact fence wrapper:** separately allow a response consisting entirely of a single ` ```json ` or plain ` ``` ` fence enclosing that same completed object, with no leading/trailing prose. Count additional choices exposed only by this wrapper. This diagnostic is not merged into the strict primary score. No regex/prose answer guessing, truncated-JSON repair, answer substitution, or gold-directed extraction occurs.

For each diagnostic report coverage and accuracy over **all attempted items**, accuracy conditional on extraction, abstention/parse status, per-variant slices, and whole-original-item bootstrap uncertainty (2,000 resamples, seed 9041). This conservative choice-only score can diagnose instruction/schema failures; it does not overwrite the original failure record or establish competence on unanswered cases.

**Position bias:** show offered-label gold frequencies, extracted-choice frequencies, and total-variation distance between choice and gold frequencies on the same answered subset. Report each variant separately and do not treat answer letters as emotion categories. Position preference can reflect question difficulty, coverage or small samples, rather than a stable trait.

Option-permutation/persona variants belong to the same original-question cluster. Human-author keys can be culturally/normatively contingent; this small coding-specialized model's performance may reflect reading, instruction following, quantization or pretraining exposure. Answering emotional-understanding questions measures keyed knowledge/application, not persistent regulation, human personality, clinical status or subjective experience. QA is not a causal hybrid-versus-ordinary comparison.

## Post-result independent audit (2026-10-25)

The frozen analysis was executed once after both completion markers existed, producing `results/multiaxis/`. It made **zero model calls**. The original raw records and strict summaries were not rewritten. The QA scorer's documented macro-F1 definition correction is source-hashed; its accuracy/Brier/log-loss/ECE/coverage results remain unchanged. This section records findings after inspection and does not change the metric definitions above.

**Software:** 48 recorded model calls, 24 completed trials, 48 action traces, 12 trials per condition. Every trial used two candidate calls, one visible diagnostic tool, one final hidden checker and one retrospective hidden checker, with a 1,024 completion-token ceiling. Every request used the same endpoint/model, temperature 0.6 and per-call ceiling 512. There were no provider errors and all 48 responses ended with `stop`, so the failures are not explained by response truncation. Seven candidate responses were rejected for source syntax/validation. Frozen weight hashes match both saved artifacts; initial snapshots are identical; paired generation seeds agree. Inspection found no private grader source or hidden-evaluation annotations in prompts.

The final suites contain **18 cases per trial**. Hybrid hidden pass fraction is **0.2917**, ordinary **0.2824**; primary paired difference **+0.00926**, 95% task-cluster interval **[−0.04167, 0.06944]**. This does not demonstrate an advantage. No final candidate passes the full suite, so correct-only efficiency is undefined rather than assigned a favorable number. No final response provides the optional confidence comment, so confidence calibration is also undefined.

Actual actions differ in **8/24** paired opportunities: **0/12** initial decisions and **8/12** second decisions. Same-hidden-suite revision is negative for both conditions (**−0.01852 hybrid; −0.06019 ordinary**). The hybrid repairs four individual cases and regresses eight; ordinary repairs none and regresses thirteen. These case observations are repeated within trials/tasks, not independent statistical samples. A comparison of public diagnostic scores against final hidden scores would have suggested improvement and would have been misleading.

Reported prompt-plus-completion expenditure is **26,837 hybrid** versus **27,308 ordinary** tokens; completion-only expenditure is **3,163** versus **3,429**. The mean-point cost-quality frontier favors hybrid descriptively, but its tiny quality contrast and frontier do not establish statistically credible dominance. Different task difficulties, small samples, quantization and runtime noise remain limitations.

Returned-code spot checks found concrete specification failures: mixed-length LRU/TTL operations were unpacked into fixed-length tuples, batching omitted cumulative capacity checks, deduplication returned keys instead of event pairs, and topological sorting omitted required cycle/lexicographic behavior. These counterexamples support the checker's failures rather than suggesting an unexplained all-suite floor. A stronger coding model or a better measured baseline is needed to test the controller in a regime with substantial full-task success.

**Live reproducibility caveat:** all twelve paired initial prompts and generation seeds are identical, but only **7/12** initial response texts match exactly. Five differ. Server caching, threading or numerical behavior may contribute; the cause was not measured. No pair was excluded on that basis. Common seeds do not guarantee common initial generated histories in this deployment. Exact recorded-response replay remains distinct from live re-execution. A prospectively shared initial candidate/history snapshot or validated deterministic server configuration would sharpen the next causal comparison.

**QA:** all 36 completed attempts (12 original questions × three variants) have exactly one provider record, no provider error, and `stop` finish reasons under the corrected 300-second timeout. All returned a JSON fence, so **strict primary accuracy and schema coverage are 0/36**. Some letter answers also have unnormalized probabilities; other responses use emotion-combination text instead of an offered letter. This is an instruction/schema failure and does not establish lack of emotional knowledge or experience.

The pre-fixed direct-completed-JSON diagnostic extracts no choices. The separate exact-fence diagnostic extracts **18/36** legal choices and scores **11/36 = 0.3056** over all attempts (conditional **11/18 = 0.6111**, coverage **0.5**; question-cluster interval **[0.1111, 0.5]**). On the twelve original base items, the same diagnostic scores **4/12 = 0.3333**, with **6/12** extractable choices and interval **[0.0833, 0.5833]**. Permuted items score 3/12 and persona items 4/12. These are secondary diagnostics; no prose, truncated JSON or illegal labels were repaired or matched to gold. Emotion text may be understandable to a person, but adding a text-to-option recovery rule after seeing outputs would be a new analysis, not this frozen diagnostic.

The interrupted earlier QA runtime artifact is preserved separately and not pooled into the clean complete study. Its exclusion was an operational timeout correction, not selection of favorable answers. The full clean study retains every attempted item. These tiny keyed-knowledge measurements are culturally/normatively contingent and potentially contaminated by pretraining; they do not measure an affect-controller benefit, clinical/personality traits or subjective experience.
